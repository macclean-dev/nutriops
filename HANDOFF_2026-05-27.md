## Decisões arquiteturais importantes

### 1. Supabase shared multi-tenant (não per-cliente)

`VITE_SB_URL` e `VITE_SB_ANON_KEY` setadas no Vercel (Production + Preview). Todos os tenants seed (Swiss, Bäckerei, DBK) usam a mesma Supabase, separados por `tenant_id` na coluna. O bloco "Sincronização Supabase" no ClientModal foi renomeado pra "Servidor dedicado (Enterprise — avançado)" e só vale pra clientes que pediram banco isolado.

### 2. Anon key compartilhada — RLS OFF (técnica débito)

Como Supabase Auth real não tá ligado (login é PIN local), RLS habilitada seria cosmética. Hoje o schema todo tem `disable row level security`. Quando o épico "Supabase Auth real" for feito, isso muda.

### 3. Hubs com sub-tabs (Nexum-style flat nav)

3 hubs no rail: `controls` (5 controles especiais), `reportsHub` (5 relatórios), `team` (users/turns/sessions). Definidos em `src/nav.js`. `isItemActive` destaca o item-pai quando uma sub-view dele está aberta.

### 4. Visão Geral v2 paralela à v1

Toggle: banner "Experimentar →" na v1 → vai pra v2. Botão "← visão antiga" na v2 volta. Cada perfil vê layout diferente. Acessível por permissions com a chave `overview-v2`.

### 5. Equipment catalog: sync por tenant

Tabela `equipment_catalog` no Supabase com PK composta `(tenant_id, label)`. Cadastro num device chama `pushEquipmentItem`; boot em outro device chama `syncEquipmentCatalog` e puxa. Cloud é source-of-truth.

### 6. `src/data.js` x `src/tenants-public.js`

`tenants-public.js` é a metadata pura — **pode commitar**. `data.js` (gitignored) adiciona `usersList` com PINs. Importa de tenants-public e faz merge. PIN reset obrigatório no 1º login protege os defaults seed.

## SQL pendente no Supabase (precisa rodar)

Se você ainda não rodou (verificar no Table Editor se as tabelas existem):

```sql
-- form_templates (templates customizados)
create table if not exists form_templates (
  id uuid primary key,
  tenant_id text not null,
  category text, frequency text,
  title text not null, description text,
  sections jsonb not null,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
create index if not exists idx_tmpl_tenant on form_templates(tenant_id);
alter table form_templates disable row level security;

-- equipment_catalog (cadastro com min/max por tenant)
create table if not exists equipment_catalog (
  tenant_id text not null,
  label text not null,
  aliases jsonb,
  location text,
  min_temp numeric,
  max_temp numeric,
  updated_at timestamptz default now(),
  primary key (tenant_id, label)
);
create index if not exists idx_eq_tenant on equipment_catalog(tenant_id);
alter table equipment_catalog disable row level security;
```

Sem essas duas tabelas, os sync de templates/catalogue falham silenciosamente.
