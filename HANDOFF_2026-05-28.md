## Decisões arquiteturais importantes

### 1. Tabela `tenants` no Supabase (separada do syncAllModules)

Tenants criados via `/admin` agora são espelhados numa tabela `tenants` no
Supabase pra suporte cross-device. SQL completo em `CLAUDE.md` → "Sync por
tenant (via Supabase)". **Status: SQL já rodado pelo usuário em 28/05.**

Schema cobre setup PIN flow (hash PBKDF2, attempts counter, lockedUntil) +
metadata do tenant pra hidratar quando cliente abre `?token=` em outro device.

### 2. Setup PIN one-time + rate limit em 2 níveis

4 dígitos é só 10000 combinações — defesa em 2 camadas:
- **PBKDF2 100k iter** — inviabiliza brute-force do hash se vazar
- **Rate limit:** 3 tentativas erradas → bloqueio 15 min (persistido em
  localStorage **+** Supabase pra resistir clear de cache)

`setup_pin_used_at` marca consumo one-time. PIN definitivo (criado após
acerto) usa `isWeakPin` pra rejeitar 0000/1234/1111.

### 3. Cmd+K como hub de navegação (Linear-style)

Antes: Cmd+K era só busca em registros (24 LoC de match). Agora:
- 25 comandos de navegação filtrados por `canAccess(role, view)`
- Ações: Quiosque, trocar tenant (multi-tenant), sair
- Recentes top 3 (localStorage `nutriops.cmdk.recent`, max 6, dedup)
- Match com NFD normalize (sem acento, case-insensitive)
- Score: label.startsWith > label.includes > keywords

`GlobalSearch` mantém export name pra zero break em imports.

### 4. Alertas operacionais com lift state pro tab badge

Computação pura (`computeTenantAlerts`) — combina métricas Supabase + clients
locais. `HealthView` sempre montado (display:none quando não-ativo) pra que
badge no tab "Saúde dos tenants" reflita estado real desde o boot, sem
exigir visitar o tab pelo menos uma vez.

Tipos:
- **inactive:** 5-9d → warn, 10+d → danger
- **compliance (últ. 7d):** <70% → warn, <50% → danger
- **trial-warning:** ≤3d → warn
- **trial-expired:** <0d → danger
- **overdue:** `billingStatus === 'overdue'` → danger

### 5. Histórico 30d via single fetch reutilizado

Antes: HealthView puxava 7d (limit 1000). Agora: puxa 30d (limit 5000) e
`metricsByTenant` filtra in-memory pros últimos 7d — economiza 1 round trip
e alimenta o sparkline da tendência sem mais código.
