## A SAGA DO SYNC (leitura obrigatória)

### Sintoma
Colaboradoras da Swiss alimentavam registros, mas não apareciam em outros
devices. Bäckerei tinha dados só até "ontem". DBK zero.

### Diagnóstico (confirmado com SQL + DevTools)
- Vercel **tinha** `VITE_SB_URL` + `VITE_SB_ANON_KEY` setadas (há 1 dia).
- Devices das lojas estavam **presos em bundle PWA antigo** (instalado antes
  das env vars existirem). O service worker versionava o cache mas **não
  forçava reload**, então o cliente nunca pegava o bundle novo com as envs.
- Pior: quando `isSupabaseEnabled()` era false, todos os pushes faziam
  `return` silencioso **sem enfileirar** — dados perdidos pra nuvem sem aviso.

### 5 bugs corrigidos
1. **Silent loss** — pushes agora enfileiram na offline.queue mesmo com
   Supabase off (cap 5000). Quando habilitar, syncQueue empurra tudo.
2. **PWA cache eterno** — toast "Nova versão disponível" + `controllerchange`
   listener que recarrega quando SW novo assume (`src/main.jsx`).
3. **401 silencioso** — `sbFetch` detecta 401/403, grava
   `nutriops.supabase.auth_error`, banner vermelho aparece (`SupabaseAuthErrorBanner`).
4. **Duplicação na queue** — regressão minha: `localRepository.create`
   enfileirava + `supabaseRepository.create` chamava ele após POST OK.
   Separado em `cacheTempLocal` (sem queue) vs `create` (com queue).
5. **testWrite UUID inválido** — health-check usava id com prefixo
   `healthcheck-` numa coluna uuid → HTTP 400. Trocado por uuid puro.

### Defesas que sobraram no código
- **Banner agressivo** (`LocalModeBanner`): conta registros locais, cor escala
  com risco (amarelo <20 → vermelho ≥100), "Dispensar 1h".
- **Health-check de write** (`supabaseRepository.testWrite`): no boot (1x/dia
  ou se há fila), faz INSERT+DELETE fake. Detecta RLS/auth/404. Limpa strays
  por `tenant_id=__healthcheck__`.
- **Logs verbosos**: boot loga `Supabase: ON/OFF | queue: N | last sync`.
  `sbFetch` loga body de qualquer 4xx (mensagem do Postgres). Pushes que
  falham logam tabela + motivo antes de enfileirar.
- **Auto-config mais agressivo** (`handleLogin`): sobrescreve config local se
  URL **ou** anon key mudaram (cobre rotação de key).
- **SUPABASE_SQL** com `alter table ... disable row level security` nas 8 tabelas.

### Estado em produção (confirmado 29/05)
- RLS está **off** em todas as tabelas (query `pg_class` confirmou).
- Swiss: 4 registros no Supabase, sync funcionando após hard-refresh do device.
- **Próximos clientes não vão sofrer o mesmo** — o toast de update + auto-config
  resolvem o problema de bundle preso.

## Decisões arquiteturais

### Code splitting (medida, não chute)
- `admin.jsx` já era lazy mas pages.jsx o importava estaticamente (linha 5)
  só por 4 funções de storage — que já existiam em `admin-storage.js`. Era
  bug de organização. Trocar o import liberou o chunk de 12.56 KB.
- Helpers de storage (load/save/readEquipmentCatalog) foram **duplicados** nos
  arquivos novos em vez de criar um `storage-helpers.js` shared. Decisão
  deliberada: 5-10 LoC vs. um módulo que toda mudança futura quebraria.
- `readCompanyProfile`/`saveCompanyProfile` movidas pra settings.jsx mas
  re-exportadas de pages.jsx (onboarding.jsx importa de './pages').

### Slim RailNav
- `buildNavSections` continua retornando 4 seções — MobileDrawer mantém "Conta"
  acessível em telas sem teclado. Só a RailNav (desktop) filtra.

### HealthView drill-down
- Reusa o array `days` já computado por `bucketByDay` — zero fetch extra.
- Modal segue padrão de ClientModal/AccessTokenModal.
