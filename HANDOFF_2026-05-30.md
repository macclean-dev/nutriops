## Itens parqueados (decisões tomadas — não são esquecimento)

### Admin password (`VITE_ADMIN_PASSWORD`) — PARQUEADO
Tentamos aposentar o fallback `••••` setando a env no Vercel.
**A env não chega no build** — provei via hash do chunk (build de prod sai
byte-idêntico ao meu build local sem a var), mesmo recriando à mão, sem cache,
com push forçando chunk novo. As `VITE_SB_*` chegam, essa não. Causa inconclusiva
(provável caractere invisível no nome, ou quirk do Vercel/Hobby).
**Decisão:** parqueado. A senha é `VITE_` → extraível do bundle de qualquer jeito,
então o ganho é marginal. O fix real é o épico de Auth (role server-side).
`/admin` segue no fallback `••••`.

### Anon key — ADIADA
Vazou num chat. **Decisão: não rotacionar.** Com RLS off, a anon key é pública
por design (vai no bundle) — rotacionar é descartável até ter RLS. A proteção
real é o épico de Auth + RLS.

> Ambos dobram no mesmo épico. Ver `docs/AUTH_RLS_PLAN.md`.

## Regras de sync que NÃO podem regredir (lições caras desta sessão)

Estão no CLAUDE.md → "Sync — entenda antes de mexer". Resumo:
- **Todo push enfileira mesmo com Supabase off** (`repository.js`) — nunca voltar
  pro `if (!enabled) return`.
- **Auto-config roda no login E no boot** (`maybeAutoConfigSupabase` em pages.jsx)
  — não reverter; foi o que destravou devices com sessão antiga.
- **Config `source:'manual'` é protegida** do auto-config (`shouldAutoConfigSupabase`)
  — pra não redirecionar dados de Enterprise com projeto dedicado.
- **Service worker força update** via toast + `controllerchange` (`main.jsx`).
- **RLS está OFF** em todas as tabelas. Se ligar Auth+RLS, reverter o
  `disable row level security` do `SUPABASE_SQL` e escrever policies `auth.jwt()`.
